Recursive vs Iterative

RecursiveIterative
Resolver obtains the final answerResolver follows referrals
Client receives the final resultEach DNS server gives the next direction
Resolver hands the lookup to the chain; each server asks the next oneResolver contacts each level itself (Root → TLD → Authoritative)
Root and TLD servers must hold state and relay the answer back (more load on them)Root and TLD answer instantly with a referral and forget the query
Resolver only learns the final answer (caches the A record)Resolver learns every referral, so it can also cache TLD NS records

How the simulation models them: In recursive mode the query travels Resolver → Root → TLD → Authoritative and the answer travels back the same chain. In iterative mode the resolver sends three separate queries and receives two referrals and one answer. Each server adds processing time every time it handles a message, so recursive is slightly slower here, and with NS caching iterative can skip the Root entirely.
